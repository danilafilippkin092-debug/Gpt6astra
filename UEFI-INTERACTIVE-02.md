# Скачать и подготовить UEFI 02

В обычном Termux (не в su), выполни:

```sh
pkg install python curl tar
cd ~
curl -fL -o DBY-W09-UEFI-interactive-02.tar.gz https://raw.githubusercontent.com/danilafilippkin092-debug/Gpt6astra/main/DBY-W09-UEFI-interactive-02.tar.gz
curl -fL -o DBY-W09-UEFI-interactive-02.tar.gz.sha256 https://raw.githubusercontent.com/danilafilippkin092-debug/Gpt6astra/main/DBY-W09-UEFI-interactive-02.tar.gz.sha256
sha256sum -c DBY-W09-UEFI-interactive-02.tar.gz.sha256
tar -xzf DBY-W09-UEFI-interactive-02.tar.gz
cd DBY-W09-UEFI-interactive-02
sha256sum -c SHA256SUMS
python uefi_test.py prepare
```

Это только подготовка. Перед `start` обязательно выполни проверку TWRP
из раздела 2 ниже. Если старый тестовый UEFI установлен, сначала верни Android.

# DBY-W09: интерактивный экспериментальный UEFI 02

**Это НЕ временный kexec/fastboot boot. Действие start заменяет раздел boot
и перезагружает планшет. Android сам не вернётся: после теста нужно восстановить
boot в TWRP. Нужны установленное работающее TWRP/OrangeFox, вход в него
аппаратными кнопками и доступ к внутренней памяти.**

На реальном планшете этот сценарий ещё не испытан. Прошли 19 тестов Python;
они не гарантируют аппаратного запуска или успешного восстановления при
непредусмотренном сбое. Меню позволяет вручную запускать EFI-приложения; закрытые EFI-драйверы
инициализируются и могут иметь побочные эффекты. Образ не подписан Huawei/AVB.

## Что проверяется

Используется DBY-W09-UEFI-interactive-02.img — интерактивный экспериментальный
UEFI с родными vendor EFI из XBL этого устройства. Его хеш проверяется.
Скрипт принимает только HWDBY / DBY-W09(S) / Kona, разблокированный
загрузчик, non-A/B и boot размером 96 МиБ. DTB и активные адреса текущего boot
должны совпасть с UEFI-кандидатом. Дополнительно проверяются отдельный
recovery с собственным ядром и неизменность recovery/recovery_ramdisk.

Никакое экспериментальное Linux-ядро из предыдущего tar.gz устанавливать
для этого теста не нужно. Этот способ запускает UEFI через штатный загрузчик.

## 1. Подготовка в Termux

Пакеты устанавливай обычным пользователем Termux, не через su:

```sh
pkg install python curl tar
cd ~/DBY-W09-UEFI-interactive-02
python uefi_test.py prepare
```

Magisk запросит root, если Termux ещё не разрешён. prepare читает boot,
создаёт проверенную резервную копию и UEFI-файл с нулевым заполнением
до размера раздела. prepare НЕ прошивает разделы и НЕ перезагружает планшет.
Нужно не менее 384 МиБ свободного места. Не удаляй каталог комплекта до
конца теста: приватное состояние хранится рядом со скриптом.

Файлы для восстановления находятся в `/sdcard/DBY-UEFI-INTERACTIVE-02/`:

- `ANDROID-BOOT-BACKUP.img` — твой оригинальный boot, 96 МиБ;
- `ANDROID-BOOT-BACKUP.img.sha256` — его контрольная сумма;
- `RESTORE-ANDROID-IN-TWRP.sh` — восстановление из терминала TWRP;
- `UEFI-TEST-BOOT.img` — тестовый образ, НЕ резервная копия.

При изменённом boot или несовпадении DTB скрипт остановится. Старые резервные
копии не перезаписываются. При STOP не пытайся обходить проверки.

## 2. Проверь реальный путь возврата

Полностью выключи планшет и войди в установленное TWRP аппаратными кнопками,
без Android, ПК и команды reboot recovery. Проверь, что видны каталог
`/sdcard/DBY-UEFI-INTERACTIVE-02/` и файл `ANDROID-BOOT-BACKUP.img` размером 96 МиБ.

В TWRP можно заранее проверить копию через Advanced → Terminal:

```sh
cd /data/media/0/DBY-UEFI-INTERACTIVE-02
sha256sum -c ANDROID-BOOT-BACKUP.img.sha256
```

Пока ничего не восстанавливай: выбери Reboot → System и вернись в Android.
Если аппаратный вход в TWRP или доступ к файлу не работают, start НЕ запускай.

## 3. Запуск UEFI

Только после предыдущего шага, в Termux:

```sh
cd ~/DBY-W09-UEFI-interactive-02
python uefi_test.py start --recovery-checked
```

Команда повторно проверяет устройство, recovery, резервную копию, UEFI
и текущий boot. Записывает только boot, сверяет прочитанный обратно SHA256
и запрашивает перезагрузку. При обнаруженной ошибке записи пытается сразу
вернуть оригинальный boot и не запрашивает перезагрузку. Откат при внезапном
отключении питания этим не гарантируется; для этого предусмотрен TWRP.

Сценарий не прошивает xbl, abl, vbmeta, dtbo, GPT, super или userdata.
Резервные копии и отчёты сохраняются как обычные файлы в памяти планшета.
Это описание сценария Python, а не гарантия поведения vendor EFI.

## 4. Что наблюдать

При успехе появится главное меню DBY-W09. Доступны:

- просмотр файловых систем и ручной запуск ARM64 `.efi`;
- встроенный EFI Shell (выход командой `exit`, autorun `startup.nsh` отключён);
- стандартный Boot Manager;
- диагностика GOP, USB, ACPI и пробное чтение LBA0 через BlockIO;
- повторное подключение USB/накопителей, перезапуск и выключение.

Громкость — выбор, Power/Enter — подтверждение, Back — возврат.
USB-клавиатура пригодится для Shell, если работает USB host. Сенсор не обещан.
FAT-флешка доступна только если vendor USB/BlockIO/SFS действительно запустятся.
Доступ к Android userdata/F2FS/ext4 и его расшифровка не реализованы.
Ручной запуск EFI-приложений и команды Shell могут изменять диски;
восстановление boot не отменяет такие изменения. Автоматической установки ОС нет.

Добавлены минимальные DSDT/FADT/MADT/GTDT по данным устройства: 8 CPU,
GICv3, PSCI SMC и таймеры. Это ещё НЕ полный набор ACPI для Windows:
периферийные устройства, питание, накопитель, USB и дисплей не описаны для неё.
Загрузка Windows 10 ARM64, ExitBootServices и runtime-службы не проверены.
Для полноценной ОС необходимы дальнейший порт ACPI и драйверов.

Запомни, появилось ли меню, работают ли кнопки, Shell, ACPI и чтение LBA0.
Чёрный экран может означать ранний сбой или отсутствие GOP-вывода.
Автоматического сохранения журнала/снимка экрана в этом образе нет.

## 5. Возвращение в Android

Аппаратно войди в TWRP тем способом, который проверил в шаге 2.
В **Advanced → Terminal TWRP** выполни:

```sh
sh /data/media/0/DBY-UEFI-INTERACTIVE-02/RESTORE-ANDROID-IN-TWRP.sh
```

Скрипт проверит SHA256 копии, найдёт boot, проверит размер 96 МиБ, восстановит
оригинал и проверит SHA256 раздела. Только после сообщения об успешной
проверке выбирай Reboot → System.

Если нужных команд в терминале TWRP нет, скрипт остановится. В качестве
ручного восстановления используй уже знакомую функцию TWRP Install → Install
Image → `ANDROID-BOOT-BACKUP.img` → **Boot**. Не выбирай Recovery/System.
Не восстанавливай файл `UEFI-TEST-BOOT.img` вместо Android-копии.

Если start остановился ещё в Android после записи или ты передумал до
перезагрузки, оригинальный boot можно вернуть из Termux:

```sh
python uefi_test.py restore
```

## 6. Один отчёт после теста

После восстановления Android, в прежнем каталоге Termux:

```sh
python uefi_test.py report
```

Опиши экран одним ответом. Скрипт создаст небольшой `UEFI-report-*.tar.gz`
в `/sdcard/DBY-UEFI-INTERACTIVE-02/`. Пришли только этот отчёт. В него включаются JSON
подготовки, запуска и состояния после возврата; образы разделов не включаются.
Если Termux не видит общую память, выдай доступ через termux-setup-storage.

## Следующий этап: Windows 10 ARM64

Эта сборка содержит базовые ACPI и ручной запуск EFI. Положительный результат
теста подтвердит работу проверенных функций UEFI, но не готовность Windows.
Затем потребуются подходящие ACPI, проверка чтения носителя и загрузочных
служб/ExitBootServices и драйверы. Разделы Windows этот комплект не создаёт.

## Проверка комплекта и исходники

```sh
sha256sum -c SHA256SUMS
```

uefi_test.py и tests/ содержат исходный код сценария. Для запуска тестов
на обычном Linux: python3 -m unittest discover -s tests -v. Тесты с
приватным эталонным boot пропускаются без KNOWN_BOOT_IMAGE. Эти тесты
не используют реальный блоковый boot и не запрашивают перезагрузку.
source/, INTERACTIVE-02.patch, UEFI-SOURCE-CHANGES.patch и LICENSE-UPSTREAM.txt
сохраняют происхождение и ограничения исходного UEFI-кандидата.

## Состав и проверка сборки

52 ARM64 EFI-модуля прошли проверку сборочной системой; 48 активных
vendor-модулей совпали с извлечёнными родными файлами, проверены
четыре RAW-ресурса. BootShim + FD, адреса загрузки и DTB проверены
относительно предоставленного рабочего boot. Проверены контрольные суммы
и включение четырёх ACPI-таблиц. Это статические проверки и имитация,
а не подтверждение запуска на реальном планшете.

Образ без подписи Huawei/AVB. Исходники изменений находятся в source/,
базовые изменения родной адаптации — UEFI-SOURCE-CHANGES.patch.
Upstream WQSQW/uefi-dby_w09, база 423e222159dfa159d788769554007455d34e6193,
сборка DEBUG CLANGPDB (Clang 19), FD 0xce000000 / 8 МиБ, ENABLE_SECUREBOOT=0.

новая версия не примет UEFI как резервную копию Android.
